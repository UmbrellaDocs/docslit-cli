# Writing DocsLit docs

DocsLit builds a static docs site from Markdown files in `docs/` plus a `docslit.json` config. Pages can embed built-in `<wc-*>` web components directly in Markdown. No imports, no MDX.

This file is generated from the component manifest (`docslit components --json`). If it disagrees with the CLI, the CLI wins.

## Workflow

Never guess a component, attribute or config key. Ask the CLI. All of these print machine-readable output and never prompt.

1. `docslit components --json` lists every component. `docslit components wc-tabs --json` returns one component's attributes, nesting rules and example.
2. `docslit schema` prints the `docslit.json` JSON Schema. `docslit schema frontmatter` prints the page frontmatter schema.
3. `docslit new guides/setup --title "Set up" --group "Guides" --description "..." --json` creates the page and registers it in the sidebar. Use it instead of hand-editing the sidebar. (Skip `--group` when the sidebar is autogenerated.)
4. Write the page content.
5. `docslit validate --format json` checks that nothing is broken: links, assets, unknown components, frontmatter, sidebar. Exit code 1 means errors.
6. `docslit lint --format json` checks quality: descriptions, headings, code languages, alt text, link text, page length. Each issue has `file`, `line`, `code`, and a `fix` hint.
7. Fix every error, then the warnings, and re-run both until they are clean. Both accept a directory argument and `--strict` (warnings fail).

`docslit mcp` starts an MCP server (stdio) that exposes the same capabilities as tools. `docslit agents init` wires it into your editor config.

Preview with `docslit dev`; build with `docslit build` (output in `dist/`).

## Project layout

```text
docslit.json        site config and sidebar
docs/               pages (*.md); sub-folders are fine
docs/_reusables/    snippets pulled in with <wc-include src="..." />
components/         optional custom components (one file per tag)
```

Page IDs map to files: `"quickstart"` is `docs/quickstart.md`, `"guides/setup"` is `docs/guides/setup.md`.

### docslit.json

```json
{
  "name": "My Docs",
  "description": "One sentence for SEO and llms.txt",
  "url": "https://docs.example.com",
  "sidebar": [
    { "group": "Getting started", "pages": ["introduction", "quickstart"] },
    { "group": "Guides", "autogenerate": "guides" }
  ]
}
```

Sidebar forms:

- Explicit: groups with a `pages` array of page IDs. Pages appear in the listed order, and every page should be listed or it is reported as an orphan.
- Per group: `"autogenerate": "folder"` (or `{ "directory": "folder", "collapsed": true }`) builds the group from a docs sub-folder.
- Whole site: `"sidebar": "auto"` derives everything from the folder tree. In auto mode order pages with frontmatter `sidebar_position` and hide one with `sidebar: false`. Do not edit the sidebar by hand to add pages; just create the file.

Other keys exist (`versions`, `i18n`, `openapi`, `theme`, `redirects`, `attributes`, `navbar`, `footer`, ...). Read `docslit schema` before adding any.

### Page frontmatter

```yaml
---
title: Set up the CLI
description: Install the CLI and run your first build in under five minutes.
sidebar_title: Set up
tag: Guide
---
```

- `title` is required. `description` should be a real sentence of 30 to 200 characters: it feeds search, SEO and `llms.txt`.
- Optional: `sidebar_title`, `tag`, `readtime` (string, e.g. `"3 min read"`), `updated`, `icon`, `draft: true`, `redirect`, `attributes` (page variables), `sidebar_position`, `sidebar`.
- Unknown keys are reported by `validate`. Check `docslit schema frontmatter`.

## Writing good pages

Pages are read by people and retrieved in chunks by LLMs. Write for both.

- One `# H1` that matches `title`, then `##` and `###` in order. Never skip a level. Do not repeat a heading text on one page (anchors collide).
- Lead with what the page is for, then the shortest working example, then detail. Prefer short sections that stand alone, since a retrieved chunk loses its neighbours.
- Every fenced code block has a language (` ```bash `, ` ```json `, ` ```text `).
- Every image has alt text that says what it shows.
- Link text describes the target ("see [the sidebar options](config)"), never "click here" or a bare URL.
- Keep pages under roughly 2500 words; split long ones. Keep paragraphs short.
- Use a component only when it beats plain Markdown: steps for ordered procedures, tabs or code groups for per-language variants, callouts sparingly (a handful per page at most), GFM tables for ordinary tables.
- Never leave `TODO`, `FIXME`, `TBD` or placeholder text in prose.
- Internal links use page slugs relative to the current page, e.g. `[Setup](setup)` or `[Setup](../guides/setup)`, without `.md`.
- Variables: define `{{NAME}}` in `docslit.json` `attributes`, page frontmatter `attributes`, or `<wc-var name="NAME" value="..." />`. Use UPPER_SNAKE_CASE. An undefined placeholder is a validate warning.

## Component rules

1. Put a blank line before and after every block-level `<wc-*>` element, and a blank line after the opening tag of any element whose body is Markdown (callouts, steps, tabs, panels, ...). Without it the body is not rendered as Markdown.
2. Do not indent component tags or their bodies by 4+ spaces: Markdown turns them into code blocks.
3. Always write explicit closing tags: `<wc-tile ...></wc-tile>`, never `<wc-tile ... />` (these are HTML custom elements, not JSX). Only the compile-time tags `wc-include` and `wc-var` (declaration form) are written self-closing: `<wc-include src="snippet.md" />`.
4. Respect nesting: containers hold only their listed children (see each component's "Children" and "Parent"). Inside `wc-tabs`, use `wc-tab`; inside `wc-steps`, `wc-step`; inside `wc-code-group`, `wc-code-tab`; and so on.
5. "raw" bodies (`wc-code-block`, `wc-code-tab`, `wc-mermaid`, `wc-asciidoc-table`) are not Markdown; write the text exactly as it should appear.
6. Use `icon-name` (not `icon`) for named icons on `wc-card` and `wc-tile`. Tabs use `label`, not `title`.
7. Pass JSON attributes with single quotes around the value: `rows='[["a","b"]]'`.
8. Do not invent tags or attributes. An unknown `wc-*` tag is a validate warning and renders as an unstyled element.
9. The `theme="dark|light"` attribute pins any themable component to a color scheme. It is omitted from the per-component lists below.
10. Migrating MDX or Mintlify content? Use `docslit import <dir>` or follow the docslit-migrate skill.

## Component reference

Generated from the manifest. "Body" says what goes between the tags.

### Callouts & text

#### `wc-callout`

Highlighted block for tips, warnings, notes and other asides. Body supports full Markdown.

- Body: markdown. Callout body. Leave a blank line after the opening tag to use block Markdown (lists, code).
- Attributes:
  - `type` (info | tip | warning | error | success | note, default `info`): Visual style of the callout.
  - `title` (string): Heading shown at the top of the callout. Omit for body-only.

```markdown
<wc-callout type="warning" title="Heads up">
Back up your `docslit.json` before running a migration.
</wc-callout>
```

#### `wc-alert`

Alias of wc-callout (same attributes and behavior).

- Body: markdown. Alert body.
- Attributes:
  - `type` (info | tip | warning | error | success | note): Visual style.
  - `title` (string): Heading shown at the top.

```markdown
<wc-alert type="error" title="Breaking change">
The `--legacy` flag was removed.
</wc-alert>
```

#### `wc-banner`

Full-width notice strip, optionally dismissible. Good for announcements inside a page.

- Body: markdown. Banner message.
- Attributes:
  - `type` (info | warning | error | success | neutral, default `neutral`): Visual style.
  - `dismissible` (boolean): Show a close button so readers can dismiss the banner.

```markdown
<wc-banner type="info" dismissible>
Version 2.0 is now available.
</wc-banner>
```

#### `wc-badge`

Small inline pill for status or category labels (Stable, Beta, Deprecated...).

- Body: text. Badge text (alternative to the label attribute).
- Attributes:
  - `variant` (default | success | warning | danger | info | neutral | purple, default `default`): Color scheme.
  - `label` (string): Badge text. If omitted, the element body is used.

```markdown
<wc-badge variant="success">Stable</wc-badge>
```

#### `wc-tooltip`

Inline text with a hover tooltip.

- Body: text. The inline text the tooltip is attached to.
- Attributes:
  - `text` (string, required): Tooltip content shown on hover.
  - `position` (top | bottom, default `top`): Where the tooltip appears.

```markdown
DocsLit uses <wc-tooltip text="A library for building web components">Lit</wc-tooltip> under the hood.
```

#### `wc-update`

Changelog entry with a version, date and change-type badge.

- Body: markdown. Description of the change.
- Attributes:
  - `version` (string, required): Version number for this change.
  - `type` (added | changed | fixed | removed | deprecated | security): Change type badge.
  - `date` (string): Release date (free-form text).

```markdown
<wc-update version="1.2.0" date="May 2026" type="added">
New `--json` flag for the `validate` command.
</wc-update>
```

### Layout

#### `wc-columns`

Responsive multi-column grid. Collapses to one column on mobile.

- Body: markdown. Column contents; each direct child block becomes one column (wrap each in a div or wc-panel).
- Attributes:
  - `cols` (number, default `2`): Number of columns.
  - `gap` (string, default `1.5rem`): Gap between columns (any CSS length).

```markdown
<wc-columns cols="2">
<div>

**Before**

Manual setup.

</div>
<div>

**After**

One command.

</div>
</wc-columns>
```

#### `wc-frame`

Bordered frame around an image or other content, with an optional caption.

- Body: markdown. Framed content, typically an image.
- Attributes:
  - `caption` (string): Caption displayed below the content.
  - `border` (boolean): Draw a border around the framed content.

```markdown
<wc-frame caption="The dashboard overview">

![Dashboard](https://example.com/dashboard.png)

</wc-frame>
```

#### `wc-panel`

Titled box that groups related content.

- Body: markdown. Panel body.
- Attributes:
  - `title` (string): Panel header text.
  - `icon` (string): Icon (emoji or short text) shown next to the title.

```markdown
<wc-panel title="Prerequisites" icon="📋">

- Node.js 20 or later
- A docs project

</wc-panel>
```

#### `wc-expandable`

Lightweight collapsible section.

- Body: markdown. Hidden content revealed on expand.
- Attributes:
  - `title` (string): Clickable heading that toggles the section.
  - `open` (boolean): Expand the section by default.

```markdown
<wc-expandable title="Show advanced options">
Set `DEBUG=1` to enable verbose logs.
</wc-expandable>
```

#### `wc-accordion`

Collapsible FAQ-style item. Usually placed inside wc-accordion-group.

- Body: markdown. Answer or detail content.
- Parent: `wc-accordion-group`
- Attributes:
  - `title` (string, required): Clickable heading text that toggles the item.

```markdown
<wc-accordion title="Which Node.js version do I need?">
Node.js 20.19 or later.
</wc-accordion>
```

#### `wc-accordion-group`

Visually connected stack of wc-accordion items.

- Body: children. One or more wc-accordion elements.
- Children: `wc-accordion`
- Attributes: none

```markdown
<wc-accordion-group>
<wc-accordion title="How do I install it?">
Run `npm install -g docslit`.
</wc-accordion>
<wc-accordion title="Is it free?">
Yes, it is Apache-2.0 licensed.
</wc-accordion>
</wc-accordion-group>
```

#### `wc-aside`

Side note or related-links box set apart from the main flow.

- Body: markdown. Aside content.
- Attributes:
  - `title` (string): Aside heading.

```markdown
<wc-aside title="Related">
See also the [quickstart](quickstart).
</wc-aside>
```

#### `wc-steps`

Numbered step-by-step procedure. Steps are numbered automatically.

- Body: children. One or more wc-step elements.
- Children: `wc-step`
- Attributes: none

```markdown
<wc-steps>

```

#### `wc-step`

A single step inside wc-steps.

- Body: markdown. Step instructions (full Markdown including code blocks).
- Parent: `wc-steps`
- Attributes:
  - `title` (string, required): Step heading shown next to the step number.
  - `n` (number): Override the auto-generated step number.

```markdown

</wc-step>
</wc-steps>
```

#### `wc-tabs`

Tabbed content switcher for alternative instructions.

- Body: children. One or more wc-tab elements.
- Children: `wc-tab`
- Attributes: none

````markdown
npm install docslit

</wc-tab>

```bash

````

#### `wc-tab`

A single tab panel inside wc-tabs.

- Body: markdown. Tab content (full Markdown). Leave blank lines around fenced code blocks.

- Attributes:

```markdown
</wc-tab>
</wc-tabs>
```

#### `wc-view`

Toggle between alternative views (for example a language or platform switcher) of the same content.

- Body: children. One or more wc-view-panel elements.
- Children: `wc-view-panel`
- Attributes: none

```markdown
<wc-view>
<wc-view-panel label="REST">

</wc-view>
```

#### `wc-view-panel`

A single panel inside wc-view.

- Body: markdown. Panel content.
- Parent: `wc-view`
- Attributes:
  - `label` (string, required): Text of the toggle button for this panel.

```markdown
<wc-view>
<wc-view-panel label="Overview">
Summary content.
</wc-view-panel>
</wc-view>
```

### Code

#### `wc-var`

Editable variable. As an element with name + default it renders an inline input; every {{NAME}} placeholder on the page updates live. As a self-closing declaration with name + value it defines {{NAME}} at build time and renders nothing.

- Body: none
- Attributes:
  - `name` (string, required): Variable name, UPPER_SNAKE_CASE by convention (letters, digits, underscore). Referenced as {{NAME}}.
  - `default` (string): Default value shown in the interactive editor before the reader changes it.
  - `value` (string): Compile-time form only: `<wc-var name="X" value="..." />` declares a page-level variable.
  - `readonly` (boolean): Prevent the reader from editing the value.

````markdown
Set your domain: <wc-var name="DOMAIN" default="docs.example.com"></wc-var>

```bash
rsync -avz dist/ deploy@{{DOMAIN}}:/var/www/html/
```
````

#### `wc-code-block`

Syntax-highlighted code with copy button, optional filename header and line numbers. Plain fenced code blocks (```lang) are usually preferred; use this tag when you need attributes like filename.

- Body: code. Raw code, shown verbatim (not parsed as Markdown).
- Attributes:
  - `language` (string): Highlighting language, e.g. javascript, python, bash, json, html, css.
  - `filename` (string): Filename displayed in the header bar.
  - `linenumbers` (true | false): Set to "true" to show line numbers.
  - `highlighted` (boolean): Content is already syntax highlighted HTML (set by the build; rarely written by hand).

```markdown
<wc-code-block language="json" filename="package.json" linenumbers="true">
{
  "name": "my-docs",
  "private": true
}
</wc-code-block>
```

#### `wc-code-group`

Tabbed group of code snippets (e.g. one per package manager or language).

- Body: children. One or more wc-code-tab elements.
- Children: `wc-code-tab`
- Attributes: none

```markdown
<wc-code-group>
<wc-code-tab label="npm">npm install docslit</wc-code-tab>
<wc-code-tab label="pnpm">pnpm add docslit</wc-code-tab>
</wc-code-group>
```

#### `wc-code-tab`

A single labelled snippet inside wc-code-group (or wc-endpoint). Content is raw text, not Markdown.

- Body: code. Raw code or command text (not parsed as Markdown).
- Parent: `wc-code-group`, `wc-endpoint`
- Attributes:
  - `label` (string, required): Tab label.

```markdown
<wc-code-group>
<wc-code-tab label="yarn">yarn add docslit</wc-code-tab>
</wc-code-group>
```

### Media & files

#### `wc-icon`

Inline icon (Lucide name or Font Awesome class).

- Body: none
- Attributes:
  - `name` (string, required): Icon name: a built-in Lucide name, or a Font Awesome class like "fa-brands fa-github".
  - `size` (number): Icon size in pixels.
  - `color` (string): Icon color (any CSS color).

```markdown
<wc-icon name="zap" size="20" color="#ff6600"></wc-icon>
```

#### `wc-files`

Container for a file/directory tree (wc-dir and wc-file).

- Body: children. wc-dir and wc-file elements.
- Children: `wc-dir`, `wc-file`
- Attributes: none

```markdown
<wc-files>
<wc-dir name="my-docs" open>
<wc-file name="docslit.json" highlight></wc-file>
<wc-dir name="docs" open>
<wc-file name="introduction.md"></wc-file>
</wc-dir>
</wc-dir>
</wc-files>
```

#### `wc-dir`

A directory node in a wc-files tree; may contain wc-dir and wc-file.

- Body: children. Nested wc-dir and wc-file elements.
- Parent: `wc-files`, `wc-dir`
- Children: `wc-dir`, `wc-file`
- Attributes:
  - `name` (string, required): Directory name.
  - `open` (boolean, default `false`): Expand the directory by default.

```markdown
<wc-files>
<wc-dir name="src" open>
<wc-file name="index.js"></wc-file>
</wc-dir>
</wc-files>
```

#### `wc-file`

A file node in a wc-files tree.

- Body: none
- Parent: `wc-files`, `wc-dir`
- Attributes:

  - `highlight` (boolean, default `false`): Highlight this file to draw attention.
  - `comment` (string): Short comment displayed after the file name.

```markdown
<wc-files>
<wc-file name="docslit.json" highlight comment="site config"></wc-file>
</wc-files>
```

#### `wc-tree`

Click-to-copy button that copies a string to the clipboard.

Lazy-loaded image with click-to-zoom lightbox and optional dark-mode variant.

### Data & API reference

#### `wc-fields`

Parameter list container for request/body/option documentation.

- Body: children. wc-field elements.
- Children: `wc-field`
- Attributes:
  - `title` (string, default `Parameter`): Section header text.
  - `header` (string): Alias of title.

```markdown
<wc-fields title="Request parameters">
<wc-field name="email" type="string" required>
A valid email address.
</wc-field>
<wc-field name="role" type="string" default="viewer" enum="admin,editor,viewer">
The user's role.
</wc-field>
</wc-fields>
```

#### `wc-field`

A single parameter/property row: name, type, flags and a Markdown description. Can nest other wc-field elements for object properties.

- Body: markdown. Field description (inline Markdown). May also contain nested wc-field elements.
- Parent: `wc-fields`, `wc-response-fields`, `wc-field`
- Children: `wc-field`
- Attributes:
  - `name` (string, required): Parameter or property name.
  - `type` (string): Data type, e.g. string, number, boolean, object, string[].
  - `required` (boolean): Mark the field as required.
  - `default` (string): Default value when omitted.
  - `deprecated` (boolean): Mark the field as deprecated.
  - `in` (header | path | query | cookie | body): Parameter location badge.
  - `description` (string): Description (alternatively put it in the element body).
  - `format` (string): Data format, e.g. uuid, email, date-time.
  - `enum` (string): Comma-separated list of allowed values.
  - `pattern` (string): Regex the value must match.
  - `minimum` (string): Minimum numeric value.
  - `maximum` (string): Maximum numeric value.
  - `minlength` (string): Minimum string length.
  - `maxlength` (string): Maximum string length.
  - `example` (string): Example value.
  - `collapsible` (boolean): Render nested wc-field children as a collapsible section.

```markdown
<wc-fields title="Parameters">
<wc-field name="user_id" type="string" in="path" required>
ID of the user.
</wc-field>
</wc-fields>
```

#### `wc-response-fields`

Like wc-fields but titled for response bodies.

- Body: children. wc-field elements.
- Children: `wc-field`
- Attributes:
  - `title` (string): Section header text.
  - `header` (string): Alias of title.

```markdown
<wc-response-fields title="Response">
<wc-field name="id" type="number">Unique identifier.</wc-field>
<wc-field name="status" type="string">Account status.</wc-field>
</wc-response-fields>
```

#### `wc-responses`

Status-code table container; holds wc-response rows.

- Body: children. wc-response elements.
- Children: `wc-response`
- Attributes: none

```markdown
<wc-responses>
<wc-response code="200" description="Success" content-type="application/json"></wc-response>
<wc-response code="404" description="User not found"></wc-response>
</wc-responses>
```

#### `wc-response`

One HTTP status-code row inside wc-responses.

- Body: none
- Parent: `wc-responses`
- Attributes:
  - `code` (string, required): HTTP status code, e.g. 200 (colored by class 2xx/3xx/4xx/5xx).
  - `description` (string): What the response means.
  - `content-type` (string): Response media type, e.g. application/json.

```markdown
<wc-responses>
<wc-response code="201" description="Created"></wc-response>
</wc-responses>
```

#### `wc-endpoint`

API endpoint header with method badge and URL; body can hold wc-fields, wc-response-fields, wc-responses and wc-code-tab code samples. With ref it is filled from the configured OpenAPI spec at build time.

- Body: children. Optional wc-fields, wc-response-fields, wc-responses, wc-code-tab (code samples) and Markdown.
- Children: `wc-fields`, `wc-response-fields`, `wc-responses`, `wc-code-tab`
- Attributes:
  - `method` (GET | POST | PUT | PATCH | DELETE): HTTP method.
  - `url` (string): Endpoint URL path.
  - `ref` (string): OpenAPI operationId to resolve against the spec in docslit.json (openapi). Populates method, url, summary, parameters and responses.
  - `summary` (string): One-line summary rendered in bold above the description.
  - `description` (string): Longer description (inline Markdown).
  - `security` (string): JSON-encoded security requirements.

```markdown
<wc-endpoint method="POST" url="/api/v1/users" description="Create a new user">
<wc-fields title="Body">
<wc-field name="email" type="string" required>Email address.</wc-field>
</wc-fields>
<wc-code-tab label="cURL">
curl -X POST https://api.example.com/api/v1/users -d '{"email":"a@b.co"}'
</wc-code-tab>
</wc-endpoint>
```

#### `wc-api-examples`

Request/response examples panel for an endpoint. Generated by `docslit openapi scaffold`; the data attribute is a JSON blob ({ responses, requestBody }) so it is rarely written by hand.

- Body: none
- Attributes:
  - `ref` (string): OpenAPI operationId this panel belongs to.
  - `method` (GET | POST | PUT | PATCH | DELETE): HTTP method.
  - `url` (string): Endpoint URL path.
  - `data` (string): JSON string of the form {"responses":[...],"requestBody":[...]} with examples.

```markdown
<wc-api-examples ref="createUser" method="POST" url="/users" data="{}"></wc-api-examples>
```

#### `wc-runnable-endpoint`

Interactive request builder: readers edit method, URL, headers and body and see the live response (real HTTP request from the browser).

- Body: none
- Attributes:
  - `method` (GET | POST | PUT | PATCH | DELETE): Initial HTTP method.
  - `url` (string): Initial request URL (use a public API or staging endpoint).

```markdown
<wc-runnable-endpoint method="GET" url="https://jsonplaceholder.typicode.com/posts/1"></wc-runnable-endpoint>
```

#### `wc-playground`

OpenAPI "Try it" panel with path/query params, auth and a response viewer. Normally generated by `docslit openapi scaffold`.

- Body: none
- Attributes:
  - `method` (GET | POST | PUT | PATCH | DELETE, default `GET`): HTTP method.
  - `url` (string, default `/`): Request path.
  - `server` (string): Base server URL prepended to the path.
  - `proxy` (string): CORS proxy URL (falls back to playground.proxyUrl in docslit.json).
  - `params` (string): JSON array describing parameters.
  - `auth` (string): JSON object describing auth, e.g. {"type":"bearer"}.

```markdown
<wc-playground method="GET" url="/users/{id}" server="https://api.example.com"></wc-playground>
```

#### `wc-schema`

Documents a named type/object schema; body holds wc-field rows.

- Body: children. wc-field elements describing the properties.
- Children: `wc-field`
- Attributes:
  - `type` (string): Type name shown in the header.
  - `description` (string): Description under the header.
  - `extends` (string): Parent type name ("extends X").

```markdown
<wc-schema type="User" description="An account holder.">
<wc-field name="id" type="string" required>Unique identifier.</wc-field>
<wc-field name="email" type="string" required>Email address.</wc-field>
</wc-schema>
```

#### `wc-table`

Table rendered from JSON passed in attributes (the component reads only the headers/rows attributes; the docs site shows a JSON-body form that the component source does not implement). For ordinary tables prefer GFM Markdown tables.

- Body: none
- Attributes:
  - `headers` (string): JSON array of header strings, e.g. ["Name","Type"]. Use single quotes around the attribute value.
  - `rows` (string): JSON array of row arrays, e.g. [["a","b"]]. Use single quotes around the attribute value.

```markdown
<wc-table headers='["Command","Description"]' rows='[["init","Scaffold a project"],["build","Build the static site"]]'></wc-table>
```

#### `wc-asciidoc-table`

Table written in AsciiDoc syntax (|=== blocks): cell spans, column specs, multi-line cells, CSV/DSV/TSV input. Rendered to a real table at build time.

- Body: asciidoc. AsciiDoc table source delimited by |=== lines.
- Attributes:
  - `cols` (string): Comma-separated column specifiers, e.g. "1,2,3" or "3*".
  - `options` (string): Comma-separated options: header, footer, autowidth.
  - `format` (psv | csv | dsv | tsv, default `psv`): Cell data format.
  - `separator` (string): Override the cell separator.
  - `stripes` (hover | even | odd | all | none, default `hover`): Row shading.
  - `frame` (all | ends | sides | none): Outer border.
  - `grid` (all | rows | cols | none): Inner lines.
  - `width` (string): Table width, e.g. "80%".
  - `caption` (string): Table title.

```markdown
<wc-asciidoc-table cols="1,2" options="header">
|===
|Flag |Meaning
|`--strict` |Treat warnings as errors
|`--json` |Machine-readable output
|===
</wc-asciidoc-table>
```

### Cards & buttons

#### `wc-card`

Clickable content card with optional icon and title.

- Body: markdown. Card body text.
- Attributes:
  - `title` (string): Card heading.
  - `href` (string): Link destination (page slug or external URL).
  - `icon-name` (string): Built-in icon name displayed on the card.
  - `icon` (string): Emoji or text icon (use icon-name for named icons).

```markdown
<wc-card title="Quickstart" href="quickstart" icon-name="zap">
Go from zero to a live site in minutes.
</wc-card>
```

#### `wc-tiles`

Responsive grid that lays out wc-tile (or wc-card) children.

- Body: children. wc-tile or wc-card elements.
- Children: `wc-tile`, `wc-card`
- Attributes:
  - `cols` (number): Number of columns. Defaults to automatic sizing.

```markdown
<wc-tiles cols="2">
<wc-tile href="installation" icon-name="package" title="Installation" description="Install the CLI."></wc-tile>
<wc-tile href="quickstart" icon-name="zap" title="Quickstart" description="Build your first site."></wc-tile>
</wc-tiles>
```

#### `wc-tile`

Compact link tile with icon, title and description.

- Body: none
- Parent: `wc-tiles`
- Attributes:
  - `title` (string, required): Tile heading.
  - `description` (string): Short description under the title.
  - `href` (string): Link destination.
  - `icon-name` (string): Built-in icon name shown above the title.
  - `icon` (string): Emoji or text icon.

```markdown
<wc-tile title="API reference" description="Every endpoint." href="api/overview" icon-name="book"></wc-tile>
```

#### `wc-button`

Call-to-action button/link.

- Body: none
- Attributes:
  - `label` (string, required): Button text.
  - `href` (string): Link destination.
  - `variant` (primary | outline | ghost | danger, default `primary`): Visual style.
  - `size` (sm | md | lg, default `md`): Button size.

```markdown
<wc-button label="Get started" href="quickstart" variant="primary" size="md"></wc-button>
```

#### `wc-prompt`

Copyable AI-prompt block with a Copy button. Use it to give readers a ready-made prompt for an AI assistant.

- Body: text. The prompt text; the Copy button copies the element text.
- Attributes:
  - `title` (string, default `AI Prompt`): Header label.

### Authoring (compile-time)

#### `wc-include`

Compile-time include of a reusable Markdown snippet from docs/_reusables. Must be self-closing; the included file cannot itself contain wc-include and its frontmatter is ignored.

- Body: none (self-closing)
- Attributes:
  - `src` (string, required): Path of the snippet. Resolved under docs/_reusables (e.g. "snippet.md" or "_reusables/snippet.md").

```markdown
<wc-include src="snippet.md" />
```

## Icons

`wc-icon name`, `icon-name` on cards and tiles, and page `icon` accept built-in Lucide-style names (for example `check`, `x`, `warning`, `info`, `arrow-right`, `external-link`, `code`, `terminal`, `file`, `folder`, `search`, `star`, `zap`, `book`, `settings`, `user`, `home`, `lock`, `package`, `globe`, `cpu`). Other names fall back to Font Awesome class names, fetched at runtime.
